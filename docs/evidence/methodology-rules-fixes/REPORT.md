```
node apply_rule_fixes.mjs --apply --only 40396,40125
```
Per methodology the script saves `container.json`, `body.before.json`, `payload.json`, `result.json`, `body.after.json` under `run-<ts>/<id>/`, checks that every removal text still matches the CURRENT body exactly (a drifted body is an anomaly, nothing is written for it), applies, re-reads, and requires the stored body to equal the simulation (rules, heuristics, principles, name, description) and the pipeline's `removed` count to match. Exit codes: 2 unhealthy, 3 deploy check failed, 4 restore problem, 5 anomaly.

## Restore recipe

Every Update writes a NEW body file and keeps the old one, so a restore is pointing the container back: `node apply_rule_fixes.mjs --restore run-<ts>` (dry run; `--apply` to do it) sends `UpdateContainer` with the saved metadata/context/storage (`object_store_path` → the old body). Manual equivalent: `UpdateContainer {container_id, updates:{storage:{...saved storage...}, metadata:{...saved metadata with the old name...}}}`. The restore path itself is only dry-run verified (it needs a prior apply to exercise).

## Caveats the operator should know

- Update appends additions at the END and exact-text retirement shifts positions: blueprint citations `m<id>:r<n>` follow positions, so the citation gate re-audits stored plans (missing refs are removed). A rewritten rule moves to the end of its list.
- Retirement matches EVERY entry with the same text: 40350's R2 and R5 share the condition “a container is run”, so the Update removes both and re-adds R5 unchanged (builder detects this generically).
- `Update` can set `name`/`description` and add/remove principles, not the regenerated bodies' `storage.*` block: the renames of 40352/40320 change the container name and the body description (what gather reads); their `storage.description` stays as is.
- Kept on purpose: 30024 H0 (CSS example is the canonical instance and carries a real-incident example that a rewrite would drop — add_heuristics stores no examples); operational timing in 40396 H2 now measurement-based; 30017's “~1GB” threshold is a measurement, not a cap.
- 40126 R5/40222 R1/40264 R3/40396 N4: retry counts and fixed delays were replaced by the observed behaviour (same error returns unchanged and the farm shows no change → treat as permanent).
