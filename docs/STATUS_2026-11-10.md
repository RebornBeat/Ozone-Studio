## B2. P2P — notify and gate, THROUGH THE MARKETPLACE, with DOWNLOAD (operator rulings 2026-11-10) — EDITED, PARSE-ONLY, not deployed
**Terminology:** "paired" in the P2P module = the operator-approved peer allow-list (`paired_peers.json`, `/network/approve-peer`). It is NOT device pairing (paired devices sync natively, separately). The MARKETPLACE flows among **connected peers** (no approval needed — it is a catalog); every other P2P message kind still requires an approved peer (default-deny unchanged).
Announcements are NOT sent to each peer one by one: an item is published to THIS instance's marketplace listing and ONE push goes to every connected peer.
| Piece | What it does |
|---|---|
| `network/mod.rs` | `MARKETPLACE_TOPIC` (every instance subscribes); `publish_to_marketplace` (listing `marketplace_published.json` + a SINGLE publish; the push names nothing — a shared topic reaches every subscriber); `MARKETPLACE_KINDS` (notify / catalog_request / catalog / fetch_request / fetch_chunk / fetch_error) accepted from ANY connected peer into `peer_marketplace_inbox.jsonl` (kept apart from the approved-peer channel, so a stranger's catalog can never surface as a finding); `send_to_connected_peer` (refuses anything that is not a marketplace kind); `spawn_marketplace_exchange` answers `catalog_request` with my listing and serves `fetch_request` ONLY for items in my published index whose body still hashes to the requested hash, in `FETCH_CHUNK_BYTES` chunks (a body is split, never refused for size); local-only `marketplace_published_bodies.json` maps an item to its body path (never sent); **`on_blueprint_created` is a no-op — blueprints are private**; items imported from a peer are not re-published (echo guard `peer_imported_items.json`) |
| `orchestrator/amt_loop.rs` bridge + `lib.rs` | publishes ONLY Methodology / JurisdictionRuleSet / Pipeline / McpEntity creations (scope markers stripped); everything else is never published. Opt-in: `auto_broadcast_sync` (default false) starts the bridge, the exchange and the import loop |
| **`orchestrator/peer_import.rs` (NEW) — the DOWNLOAD** | acts only on offers the operator decided `download` on: **methodology** → `fetch_request`, chunks reassembled, hash RE-VERIFIED (altered / truncated = rejected), validated as a JSON object, imported through the normal create path (`store.create_container` under the methodology root → write-time keyword gate → pending → settlement validation; no shortcut) with the body stored BYTE-FOR-BYTE so its hash matches the peer's; same name + same hash = `have`; same name + different hash = a distinct name `"… (from peer xxxxxx)"` — both kept, never overwritten. **jurisdiction rule set** → fetched, validated as `JurisdictionContentFile` (mandatory disclaimer, rules present) and only STAGED under `peer_staging/jurisdiction/` — never registered, never active. **tool / pipeline** → approval recorded, nothing fetched (executables need a human, reviewed install). Outcomes in `peer_import_done.json`; a request unanswered for 15 min = `failed` (re-deciding `download` retries) |
| `grpc/mod.rs` marketplace | `peer_offers` (from `announce` and `catalog` rows; gate: `have` / `conflict` / `new` by name + hash; each offer carries its `import` outcome), `published`, `POST /marketplace/offers/decide` (`download` / `ignore` / `pending`; a fresh `download` clears a failed outcome) |
| UI (`MarketplacePanel.tsx`, `ozoneClient.ts`) | "Offers and downloads from peers": each offer with type, have/conflict/new, decision/import status, Approve download / Ignore; NOT type-checked |
| **The door** | `network::sanitize_marketplace_message`: nothing not allowed is accepted — allow-listed item types only, strict shapes, scope markers stripped from peers' keywords, unknown fields dropped, abuse guards; refusals logged to `peer_marketplace_rejected.jsonl` and counted in the overview (`exchange.refused_inbound`) |
| **The review gate** | `orchestrator/offer_review.rs`: ADVISORY recommendation per offer (download / ignore / review) — identical content decided mechanically, otherwise strength-N zero-shot judged from the manifest alone; unanimity for either extreme; stored in `peer_offer_reviews.json`; NEVER acts (E27 in the expansion guide, row 31 of the call registry) |
| **UI (reworked)** | `MarketplacePanel`: Connected peers (live) + Peer offers stats (pulsing when something waits), "Installed & Offers" tab with an animated badge, `OfferRow` (type, have / conflict / new, the gate's recommendation, decision / import status in fixed colours, spinner + progress bar while downloading, Approve / Ignore), "Publish & Policy" tab (live publishing state, the published list, a policy that matches the code — the stale "peer catalogs are not exchanged" / "paired peers" / disabled-publish text is gone), a refused-at-the-door notice; `prefers-reduced-motion` respected; syntax-parse clean, NOT type-checked |
| Tests written (not run) | `peer_import`: offer-key parsing, distinct-name import, exact reassembly + hash, validation refusals, slugs; `network`: chunking (never cuts a character), marketplace-kind recognition, stable body hash |
